# Демонстрация сайта питомника Анисимова

Рабочая демонстрационная версия обновлённого сайта небольшого питомника Геннадия Павловича Анисимова в Томске. Проект показывает, как могут выглядеть современный каталог, мобильная версия и сбор заявки без рекламы, регистрации и серверной отправки писем.

Предпросмотр после публикации: **https://nst0v.github.io/pitomnik-anisimova-demo/**

## Что реализовано

- 17 реальных позиций из четырёх разделов исходного каталога;
- поиск по названию, латинскому названию и исходному номеру;
- фильтр по категориям и понятное состояние без результатов;
- подробная карточка с описанием, ценой, единицей продажи и ссылкой на источник;
- добавление в заявку, изменение количества и удаление;
- сохранение заявки и заполненных контактов в `localStorage`;
- расчёт стоимости позиций без доставки;
- формирование текста, копирование заявки и открытие готового письма через `mailto:`;
- адаптивная вёрстка с крупными элементами управления;
- автоматическая публикация в GitHub Pages.

Сайт не отправляет письма самостоятельно и не показывает ложное сообщение об отправке. Кнопка «Открыть письмо» передаёт подготовленный текст в почтовое приложение пользователя, где письмо нужно проверить и отправить вручную.

## Запуск

Требуется Node.js 24 и npm.

```bash
npm install
npm run dev
```

Vite напечатает локальный адрес, обычно `http://localhost:5173`.

Проверка production-сборки:

```bash
npm run build
npm run preview
```

Браузерные тесты используют установленный Google Chrome:

```bash
npm run test:e2e
```

Точечные проверки исправлений поиска, резервного копирования и текста заявки (без перезапуска браузерного набора):

```bash
npm run test:audit
```

Ветка проверки также сохраняет кнопку закрытия мобильной заявки при прокрутке, показывает предупреждение при невозможности сохранить черновик и явно маркирует архивные условия. Текст письма содержит краткую строку исходных номеров (`42-2, 176`), единицы продажи и пометку о демонстрации. Наличие и цены в данных не изменялись.

## Где лежат данные

Каталог вынесен в [`src/data/plants.ts`](src/data/plants.ts). Чтобы добавить растение, достаточно создать ещё один объект типа `Plant`; менять компоненты не требуется. Цена имеет тип `number | null`: позиции без опубликованной цены не попадут в итоговую сумму молча.

Фотографии есть у всех 17 растений и хранятся локально в [`public/images`](public/images). Восемь снимков перенесены из фотоархива питомника, девять недостающих добавлены из Wikimedia Commons. Дополнительные снимки показывают внешний вид растения, не конкретные экземпляры питомника: в карточках и подробностях стоят пометка «Иллюстрация», автор, источник и лицензия. Полные сведения и изменения файлов — в [`public/IMAGE_CREDITS.md`](public/IMAGE_CREDITS.md).

## Известные ограничения и вопросы владельцу

1. Каталог сезона 2025–2026 уже истёк. Более того, страница каталога указывает срок до **1 октября 2026 года**, а страница «О нас» — до **1 ноября 2026 года**. Актуальный сезон нужно подтвердить.
2. Наличие каждой позиции, цены, скидки, сроки рассылки и тарифы 390/550 ₽ требуют повторной проверки владельцем.
3. На старом сайте опубликованы банковские реквизиты. В демоверсию они намеренно не перенесены; безопаснее сообщать актуальные реквизиты после подтверждения заказа.
4. В перечне альтернативной доставки OZON упомянут только в одном из двух фрагментов страницы «Как заказать», поэтому этот способ требует уточнения. Яндекс Доставка, «Пятёрочка» и СДЭК также должны быть подтверждены.
5. Старый общий альбом «Яндекс‑Фото» недоступен при проверке. Сохранены восемь ранее доступных авторских файлов. Остальные девять карточек используют подписанные иллюстрации из Wikimedia Commons; при получении фотографий от владельца их можно заменить снимками конкретного посадочного материала.
6. Возраст владельца и формулировка о номере сезона быстро устаревают, поэтому в демоверсии не используются.
7. Описания лекарственных растений перенесены как сведения исходного каталога; перед публичным запуском формулировки стоит отдельно согласовать и добавить юридически корректное предупреждение.
8. Прямая отправка формы отсутствует: для неё после согласования понадобятся серверный обработчик, политика обработки персональных данных и выбранный почтовый сервис. SMTP-доступы для демонстрации не нужны.

## Что потребуется для полноценного запуска

- подтверждённый каталог нового сезона со всеми позициями, актуальными ценами и наличием;
- оригиналы фотографий и разрешение владельца на их публикацию в новой версии;
- подтверждённые контакты, способы оплаты, доставки, скидки и календарь рассылки;
- решение по домену и хостингу;
- согласованный текст политики конфиденциальности, если появится серверная форма;
- серверная отправка писем или другой канал обработки заявок, если владелец решит отказаться от `mailto:`;
- финальная проверка владельцем текстов и тестовый заказ без фактической оплаты.

## Проверка качества

Playwright-тесты проверяют ширины 360, 390, 768 и 1440 px, отсутствие горизонтального переполнения и битых изображений, поиск, фильтры, пустую выдачу, подробности, количество, удаление, сохранение после перезагрузки, копирование заявки и содержимое `mailto:`. Последний локальный прогон: **7 тестов успешно**. Production-сборка выполняется командой `npm run build`.
